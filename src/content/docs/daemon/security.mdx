There is no permissive mode and no static password. The secret never travels over the wire.

## Request signing

Every request carries three headers:

| Header | Content |
|---|---|
| `x-mono-ts` | Unix timestamp in seconds |
| `x-mono-nonce` | A single-use random value, 16 to 64 characters |
| `x-mono-sig` | Hex HMAC-SHA256 signature |

The signature covers a canonical string made of the timestamp, nonce, uppercase method, path with query string and the SHA-256 hash of the exact body, each on its own line. Streaming routes use the marker `UNSIGNED-PAYLOAD` instead of a body hash, and verify a checksum carried in the signed query string.

```text
{ts}\n{nonce}\n{METHOD}\n{path?query}\n{sha256(body)}
```

## Checks

1. If `ALLOWED_IPS` is set, the caller's IP must be in it, or the daemon answers `403`.
2. The headers must be present and well formed.
3. The timestamp must be within 60 seconds of the daemon's clock.
4. The nonce must not have been seen before, which stops replays.
5. The signature must match, compared in constant time.

These cheap checks run before the request body is read, so unauthenticated clients cannot make the daemon buffer large uploads.

## Hardening

- Server ids are validated, and file paths are confined to the server volume with symlinks refused.
- Downloads block private addresses.
- Containers drop all capabilities, forbid privilege escalation, and are limited in RAM, swap, CPU and processes.
- Only images whose name starts with a prefix in `ALLOWED_IMAGE_PREFIXES` are pulled, when it is set.
- Use `TLS_CERT` and `TLS_KEY`, or a private network, when the panel and node are on different networks.
- Run the daemon as a dedicated unprivileged user, with `NoNewPrivileges=true` in the systemd unit.

Keep the clocks of the panel and every node in sync (NTP), because the signature window is only 60 seconds.
