`RUNTIME=auto` (the default) tries the Docker socket first, then Podman, then the native process sandbox.

| Setting | Meaning |
|---|---|
| `CONTAINER_SOCKET` | `/var/run/docker.sock`, `/run/podman/podman.sock` or `//./pipe/docker_engine` on Windows |
| `OCI_RUNTIME` | `runsc` (gVisor), `kata` or `sysbox-runc` for stronger isolation |
| `RUNTIME=process` | No container engine. For OpenVZ, LXC, Termux and tiny VPSes. Install `bubblewrap` for namespace and read-only-root isolation |
| `PROCESS_SANDBOX` | `auto`, `bwrap` or `none` |
| `ALLOWED_IMAGE_PREFIXES` | Only pull images whose name starts with one of these |

## Resource limits

Containers are limited in RAM, swap, CPU and processes. The daemon enforces disk quota itself, and a server that exceeds it is stopped.

## Ports

The panel allocates host ports for each server inside `PORT_MIN` to `PORT_MAX`. Keep the VPS SSH range (42000 to 42999 by default) outside it.

## Checking a node

`GET /v1/ping` reports the daemon version, runtime, platform, architecture, hostname, whether TLS is on, the port range, and which features (servers, VPSes) and hosting types (`services`) are enabled. `GET /v1/system` reports CPU count, load, memory, disk, uptime and the number of servers and VPSes.
