title: "Daemon State"
description: "What the daemon stores in PostgreSQL."

---

The daemon stores everything it needs to remember in PostgreSQL (`DATABASE_URL`): server definitions, installer progress and the recycle-bin index. There is no SQLite file and no JSON state file.

Tables are created on first start: `daemon_servers`, `daemon_installs`, `daemon_recycle` and `daemon_meta`. Change the prefix with `DATABASE_TABLE_PREFIX`.

- Use **one database (or one table prefix) per node.** A second daemon on the same database is refused on purpose.
- The daemon keeps a copy in memory so reads are instant, and every write goes to PostgreSQL first. If PostgreSQL is down the daemon refuses to start, and changes that need the database fail instead of being half applied.
- Behind PgBouncer, use session pooling. Transaction pooling cannot hold the single-daemon lock.
- Server files live under `DATA_DIR` and are not in the database. Back up both.
- `DATABASE_SSL`, `DATABASE_SSL_CA` and `DATABASE_POOL_MAX` (default 3) work like their panel counterparts.
