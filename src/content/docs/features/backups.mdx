Backups are archives of a server's files, kept on the node.

## How they work

The daemon creates a `.tar.gz` of the server volume (skipping `node_modules` and `.cache`), records its size and a SHA-256 checksum, and returns them to the panel. If the archive is larger than the storage the plan allows, it is discarded and the request fails.

The number of backups a server can keep is its `backups` limit. A server with no backup slots cannot create backups or backup schedule tasks.

## Restore

Restoring checks every path in the archive first and refuses archives containing absolute paths or `..`. Only then does it empty the server volume and extract the archive. Restoring replaces the current files, so take a fresh backup first if you need to keep them.

## Download and delete

A backup can be downloaded as a file from the panel and deleted to free the slot. Deleting a server removes all of its backups.

## Automation

Add a `backup` task to a [schedule](/docs/features/schedules/) to create backups automatically. Team members need the `backups` permission.
