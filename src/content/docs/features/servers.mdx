A server is an isolated app or bot that runs on a node. Customers create servers from the software you offer, and each server gets its own limits.

Every server has a **kind**: `bot`, `nodejs`, `website` or `lavalink`. The kind comes from the software it was created from, it is stored with the server and it can never change afterwards. Servers made before kinds existed count as `bot`. Each kind adds its own tabs to the server page, see [Website hosting](/docs/features/websites/), [Node.js hosting](/docs/features/nodejs/) and [Lavalink hosting](/docs/features/lavalink/).

## Limits

Every plan defines per-server limits, and a server keeps a snapshot of the limits it was created with:

| Limit | Meaning |
|---|---|
| `ramMB` | Memory in MB |
| `cpuPercent` | CPU share, where `100` is one full core |
| `diskMB` | Disk quota, enforced by the daemon |
| `swapMB` | Swap in MB |
| `pids` | Maximum processes |
| `backups` | Backup slots |
| `databases` | Databases per server |
| `ports` | Extra host ports besides the software's defaults |
| `subusers` | Team members (needs the sub-user plan feature) |
| `schedules` | Scheduled tasks (needs the scheduled tasks plan feature) |

Plans can also set whole-account ceilings for RAM, CPU and disk.

## Server states

A server is always in one of these states: `installing`, `offline`, `running`, `starting`, `suspended`, `expired`, `install_failed` or `transferring`.

## Power actions

The power controls are **start**, **stop**, **restart** and **kill**. They are also available to schedules, and team members need the `power` permission.

## Creating a server

1. The customer picks the software, a node (or the panel picks one) and a plan. Only nodes that serve the software's kind are offered, and a plan can be limited to some kinds.
2. The panel checks that the hosting type is switched on, plan limits, free node capacity and free ports in the node's port range.
3. The panel registers the server on the daemon and starts the install.
4. When the install finishes, the server is offline and ready to start.

## Expiry

Servers on plans with a validity period expire. When `expiresAt` is reached the server is stopped and marked `expired`. If it is not renewed within 24 hours it is deleted and its volume is wiped. That 24-hour grace period is a constant, not a setting. See [Coins and renewals](/docs/features/coins-and-renewals/).
