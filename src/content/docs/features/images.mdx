Each piece of software (called an image in the admin panel) describes how to install and run something.

## What a definition holds

| Field | Purpose |
|---|---|
| Name, software label, category | What customers see in the Software dropdown |
| Docker images | One or more labelled images, with a default |
| Startup | The start command, with `{{VAR}}` and `{{SERVER_PORT}}` substitution |
| Stop command | Sent to stop the server cleanly |
| Ports | Container ports the server listens on |
| Variables | Environment variables, with defaults and validation rules, optionally editable by the customer |
| Install | An image, a shell entry point and an install script, plus files to download |
| Runtime | `any`, `container` or `process` |
| Minimum RAM | Smallest allowed limit |

## Shipped by default

Node.js, Python, Static Website (Python `http.server`) and Minecraft (Paper). The Node.js definition uses the same variables and startup flow as the generic Node.js egg on Pterodactyl panels: Git repo address, branch, auto update, extra packages, main file and arguments. Node.js 20, 22, 24 and 25 images are listed.

## Startup tab

Customers can edit the variables an admin marked as editable, such as the main file, on the server's Startup tab. Values are checked against each variable's rules, so a customer cannot inject arbitrary text.

You can test a definition from the admin panel before offering it.
