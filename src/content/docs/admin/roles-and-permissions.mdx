## Account roles

| Capability | `user` | `support` | `moderator` | `admin` | `super_admin` |
|---|:-:|:-:|:-:|:-:|:-:|
| Customer dashboard | Yes | Yes | Yes | Yes | Yes |
| Answer support tickets | No | Yes | Yes | Yes | Yes |
| Send mail (one user or broadcast) | No | Yes | Yes | Yes | Yes |
| Reach the admin API (basic admin routes) | No | Yes | Yes | Yes | Yes |
| Publish status incidents | No | No | Yes | Yes | Yes |
| Hosting admin, VPS admin and Discord manager bot controls | No | No | No | Yes | Yes |
| API keys and security tools | No | No | No | Yes | Yes |

The admin area is built on role checks in `server/auth.ts` and each route file. Support and moderator accounts can use the shared admin routes that their role is allowed to reach, while the hosting, VPS and manager bot consoles are limited to `admin` and `super_admin`. A user's role can be set to any of the five roles by an admin. Admin and super admin accounts can still sign in during maintenance mode, while other roles are blocked.

## Server team access

A server's owner can do everything on it. Owners can also share a server with other accounts and grant each person only some of these permissions:

| Permission | Allows |
|---|---|
| `console.read` | Watch the live console |
| `console.command` | Send console commands |
| `power` | Start, stop, restart and kill |
| `files.read` | Browse and download files |
| `files.write` | Edit, upload, move and delete files |
| `backups` | Create, restore and delete backups |
| `schedules` | Manage scheduled tasks |
| `addons` | Install and remove addons |
| `sftp` | Manage SFTP access |
| `settings` | Change server settings |

Team access depends on the owner's plan. If the owner's plan does not include sub-users, team members lose access until the plan returns. See [Team access](/docs/features/subusers/).
